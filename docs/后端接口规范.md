# 校园二手交易平台 · 后端接口规范（v1.0 定稿）

> 起草：后端开发　状态：**已由项目总控审定（2026-11-18）**。表结构以 `sql/schema.sql` 为准，本文不涉及表字段。

## 1. 技术版本
| 项 | 版本/选型 |
|---|---|
| JDK | 17 |
| Spring Boot | 3.2.x |
| 安全 | Spring Security 6 + JWT（jjwt 0.12） |
| ORM | MyBatis-Plus 3.5.x |
| 数据库 | MySQL 8.0，utf8mb4 |
| 缓存 | Redis 7（Spring Data Redis + Lettuce） |
| 即时通讯 | WebSocket + STOMP |
| 文件存储 | MinIO（主），本地磁盘（降级，配置开关切换） |
| 接口文档 | Knife4j（OpenAPI 3），地址 `http://localhost:8080/doc.html` |

## 2. 基础约定
- 服务端口 `8080`，无 context-path。
- 统一前缀 `/api/v1`，按模块划分：`/api/v1/auth`、`/users`、`/goods`、`/categories`、`/orders`、`/reviews`、`/chat`、`/files`、`/admin/**`、`/recommend`、`/price`。
- RESTful：GET 查、POST 增、PUT 全量改、PATCH 局部改/状态变更、DELETE 删；资源名用复数名词，状态动作用子资源，如 `PATCH /api/v1/orders/{id}/status`。
- 请求/响应体 JSON，字段 camelCase。
- 时间格式 `yyyy-MM-dd HH:mm:ss`，时区 Asia/Shanghai。
- 主键用 MyBatis-Plus 雪花 ID（Long），**序列化为字符串**，避免前端 JS 精度丢失。
- 金额用 `BigDecimal`，保留 2 位小数，JSON 中输出为数字。

## 3. 统一返回格式
```json
{ "code": 200, "msg": "success", "data": { } }
```
- `code=200` 表示成功；其他值表示失败，`data` 为 null。
- HTTP 状态码：成功 200；未登录/Token 失效返回 **HTTP 401**；无权限 **HTTP 403**；其他业务错误统一 HTTP 200 + 业务 code（前端统一看 `code`）。
- 参数校验失败：`code=400`，`msg` 为第一条校验信息。

## 4. 分页
- 请求参数：`pageNum`（从 1 开始，默认 1）、`pageSize`（默认 10，最大 100）。
- 返回 `data`：
```json
{ "records": [], "total": 123, "pageNum": 1, "pageSize": 10, "pages": 13 }
```

## 5. 错误码分段
| 区间 | 含义 |
|---|---|
| 200 | 成功 |
| 400 / 401 / 403 / 404 / 500 | 通用：参数错误 / 未登录或Token失效 / 无权限 / 资源不存在 / 系统异常 |
| 10000–10999 | 用户与认证（如 10001 用户名已存在，10002 账号或密码错误，10003 学生认证未通过，10004 账号已封禁） |
| 20000–20999 | 商品与分类（20001 商品不存在，20002 商品已下架，20003 非本人商品） |
| 30000–30999 | 订单（30001 订单状态不允许此操作，30002 不能购买自己的商品，30003 商品已被预订） |
| 40000–40999 | 聊天消息 |
| 50000–50999 | 评价与信誉（50001 已评价，50002 订单未完成不可评价） |
| 60000–60999 | 后台管理与审核 |
| 70000–70999 | 文件上传（70001 文件类型不支持，70002 文件过大） |
| 80000–80999 | 推荐与价格建议 |

## 6. 认证（JWT）
- 请求头：`Authorization: Bearer <accessToken>`。
- 登录 `POST /api/v1/auth/login` 返回 `{ accessToken, refreshToken, expiresIn, userInfo }`。
- accessToken 有效期 2 小时；refreshToken 7 天，存 Redis。刷新：`POST /api/v1/auth/refresh`。
- 过期或无效：HTTP 401 + `{code:401, msg:"登录已过期"}`，前端拿 refreshToken 刷新，失败则跳登录。
- 退出 `POST /api/v1/auth/logout`：accessToken 加入 Redis 黑名单至过期，删除 refreshToken。
- 角色：`USER`、`ADMIN`；管理端接口统一 `/api/v1/admin/**`，需 ADMIN 角色。
- 白名单（游客可访问）：登录、注册、验证码、商品列表/详情、分类、搜索、首页推荐（未登录走热度/冷启动）。

## 7. 即时聊天（STOMP）
- 端点：`/ws`（同时开启 SockJS 兼容：`/ws` 带 SockJS）。
- CONNECT 帧头携带 `Authorization: Bearer <token>`，服务端在 ChannelInterceptor 中校验。
- 发送：`/app/chat.send`，消息体 `{ toUserId, goodsId, content, type }`（type：1 文本 2 图片 3 商品卡片）。
- 接收：订阅 `/user/queue/messages`；已读回执订阅 `/user/queue/read`。
- 历史消息与会话列表走 HTTP：`GET /api/v1/chat/sessions`、`GET /api/v1/chat/sessions/{sessionId}/messages?pageNum=&pageSize=`。

## 8. 文件上传
- `POST /api/v1/files/upload`，`multipart/form-data`，字段 `file`；返回 `{ url, name, size }`。
- 仅图片 jpg/jpeg/png/webp，单张 ≤ 5MB；商品图最多 9 张。
- `storage.type=minio|local` 切换；MinIO 不可用时自动降级到本地 `/uploads`，静态映射 `/files/**`。

## 9. 智能模块接口（总控已确认）
- `GET /api/v1/recommend/home?size=`：当前用户取自 JWT，未登录走热度/冷启动。
- `GET /api/v1/recommend/similar/{goodsId}?size=`
- 两个推荐接口返回 GoodsVO 列表，每项额外带 `reason`（推荐理由文案）和 `reasonType`（枚举 CF / INTEREST / HOT），其他商品接口不返回这两个字段：
  - `CF`：基于你浏览或收藏过的相似商品（协同过滤或内容相似），如「你收藏过类似的 iPad」「和你浏览过的高等数学相似」；相似推荐页一般为「和当前商品相似」。
  - `INTEREST`：匹配你的兴趣分类，如「你关注了数码电子」。
  - `HOT`：热度推荐（游客、冷启动或候选不足时补齐），如「本周热门」。
  - 首页候选顺序：CF → 兴趣分类 → 本周热门（HOT）→ 最新发布（HOT）；仍不足 size 时用「只浏览过（未收藏/聊天/下单）、仍在售、非自己发布」的商品按最近浏览倒序补在末尾，reasonType=CF，reason=「你最近浏览过，还在售」。自己发布的、收藏/聊天/下单过的商品不推荐。每个商品只由一个通道放入，即其主要得分来源。
  - 完整文案集：CF「你{买过/咨询过/收藏过/浏览过}类似的{标题}」「和你{…}的{标题}相似」「和当前商品相似」「和你兴趣相似的同学也看过」「和你看过的商品相似」「你最近浏览过，还在售」；INTEREST「你关注了{分类}」「你常逛{分类}」；HOT「本周热门」「最新发布」。长标题截断加「…」。
  - 文案由推荐算法根据实际命中来源生成，长度不超过 30 字；前端按 reasonType 选择标签样式，直接展示 reason。
- `POST /api/v1/price/suggest`
- 行为表 `user_behavior(id, user_id, goods_id, behavior_type TINYINT, create_time)`，索引 `(user_id,goods_id)`、`(goods_id,behavior_type)`；取代原 browse_history，DDL 以 schema.sql 为准。
- behavior_type：1 浏览、2 收藏、3 聊天、4 下单；权重 1/3/4/5（智能算法已确定，可配置）。
- 后端在商品详情（1）、收藏（2）、发起聊天（3）、下单（4）接口中用 @Async 异步写入行为记录；浏览按同一用户同一商品 30 分钟去重（Redis key `behavior:view:{userId}:{goodsId}`，TTL 30min）；游客不记录。

## 10. 接口路径清单（后端定义，均在 /api/v1 下；枚举取值以 schema.sql 为准，出来后补齐）
**认证** `GET /auth/captcha` → `{captchaKey, imageBase64}`；`POST /auth/register` `{username, password, phone?, captchaKey, captchaCode}`；`POST /auth/login` `{account, password, captchaKey, captchaCode}`（account 可为用户名/手机号/学号）；`POST /auth/refresh` `{refreshToken}`；`POST /auth/logout`
**用户** `GET/PUT /users/me`；`PUT /users/me/password`；`POST /users/me/student-verify` `{studentNo, realName, school, cardImageUrl}`；`GET /users/me/goods`（我的发布，可带 status）；`GET /users/me/favorites`；`GET /users/{id}`（公开主页+信誉分）；`GET /users/me/interests` → CategoryVO[]；`PUT /users/me/interests` `{categoryIds:[]}`（整体覆盖，最多 5 个，仅 ENABLED 分类，超出/非法返回 400）
**商品** `GET /goods`（列表，参数 categoryId/minPrice/maxPrice/condition/sort）；`GET /goods/search?keyword=`；`GET /goods/{id}`；`POST /goods`；`PUT /goods/{id}`；`PATCH /goods/{id}/status` `{status}`（卖家上/下架）；`DELETE /goods/{id}`；`POST /goods/{id}/favorite`、`DELETE /goods/{id}/favorite`
**分类** `GET /categories`（平铺）、`GET /categories/tree`
**订单** `POST /orders` `{goodsId, remark?}` → OrderVO；`GET /orders?role=buyer|seller&status=&pageNum=&pageSize=`（role 默认 buyer）；`GET /orders/{id}`（仅买家/卖家/管理员）；`PATCH /orders/{id}/status` `{action: PAY|CONFIRM|CANCEL|REFUND, reason?}` → OrderVO
**评价** `POST /reviews` `{orderId, score(1-5), content?(≤500)}` → ReviewVO；`GET /reviews?userId=&pageNum=&pageSize=`（某用户收到的评价，游客可看）
**聊天** `POST /chat/sessions` `{goodsId, toUserId}`（已存在则返回原会话）→ ChatSessionVO；`GET /chat/sessions` → ChatSessionVO[]（不分页，按最近消息时间倒序）；`GET /chat/sessions/{sessionId}/messages?pageNum=&pageSize=`（pageNum=1 为最新一页，页内按 create_time 升序）；`PATCH /chat/sessions/{sessionId}/read` → `{sessionId, readerId, readCount}`；STOMP：`SEND /app/chat.send`，订阅 `/user/queue/messages`、`/user/queue/read`（载荷 `{sessionId, readerId}`）、`/user/queue/errors`（载荷 `{code, msg, data:null}`）
**文件** `POST /files/upload`
**智能** `GET /recommend/home?size=`；`GET /recommend/similar/{goodsId}?size=`；`POST /price/suggest`
**管理端（ADMIN）** 商品：`GET /admin/goods/audits?pageNum=&pageSize=`（待审核，先提交先审，返回完整 GoodsVO：含 description、images、seller）；`PATCH /admin/goods/{id}/audit` `{result: APPROVE|REJECT, reason?}`（APPROVE→ON_SHELF，REJECT→REJECTED 且 reason 必填）；`GET /admin/goods?keyword=&categoryId=&status=`（任意状态，不含已删除；keyword 匹配标题/描述，categoryId 含子分类；另支持 sellerId）；`PATCH /admin/goods/{id}/status` `{status: ON_SHELF|OFF_SHELF}`。用户：`GET /admin/users?keyword=&status=`（keyword 匹配 username/phone/student_no/nickname；另支持 role；AdminUserVO = UserMeVO + lastLoginTime）；`PATCH /admin/users/{id}/status` `{status: NORMAL|BANNED}`。学生认证：`GET /admin/student-verifies?status=`，列表项 `{id, userId, username, nickname, realName, studentNo, school, cardImageUrl, status, reason, createTime}`；`PATCH /admin/student-verifies/{id}` `{result: APPROVE|REJECT, reason?}`。统计：`GET /admin/stats?days=7|30`（默认 7，其他值 400）→ `{userCount, goodsCount(不含已删除), orderCount, gmv(COMPLETED 订单 price 之和，数字), pendingGoodsAudit, pendingStudentVerify, trend:[{date:'yyyy-MM-dd', newUsers, newGoods, newOrders}]（days 条，含今天，升序，无数据补 0）, categoryShares:[{categoryId, categoryName, count}]（未删除商品按一级分类聚合，子分类计入父分类，按 count 倒序）, hotGoods:[{id, title, coverUrl, price, viewCount, favoriteCount}]（未删除商品按 view_count 倒序 Top10，任意状态）}`。举报：`GET /admin/reports?status=`；`PATCH /admin/reports/{id}` `{result: APPROVE|REJECT, remark?}`。公告：`GET /admin/announcements?status=`、`GET /admin/announcements/{id}`、`POST /admin/announcements` `{title, content, status?: DRAFT|PUBLISHED}`、`PUT /admin/announcements/{id}` `{title, content}`、`PATCH /admin/announcements/{id}/status` `{status: DRAFT|PUBLISHED|OFF_SHELF}`、`DELETE /admin/announcements/{id}`
**举报** `POST /reports` `{targetType: GOODS|USER, targetId, reason(≤64), detail?(≤500)}` → ReportVO
**公告** `GET /announcements`（游客可看，仅 PUBLISHED，按发布时间倒序分页）；`GET /announcements/{id}`

## 11. 主要 VO 字段与枚举（依据 schema.sql）
- **GoodsVO**：id, title, description, price, originalPrice, condition, tradeMethod, status, categoryId, categoryName, coverUrl, images(string[]，按 sort_no), viewCount, favoriteCount, favorited(boolean，游客 false), auditReason(仅本人/管理员可见), seller{id, nickname, avatar, creditScore, school}, createTime。列表接口不返回 description、images。
- **CategoryVO**：id, parentId, name, sort；树接口额外带 children[]。
- **UserPublicVO**（GET /users/{id}）：id, nickname, avatar, creditScore, school, studentVerified(boolean), createTime。
- **UserMeVO**（GET /users/me）：id, username, nickname, avatar, phone, studentNo, school, role, status, creditScore, studentAuthStatus, createTime。
- **登录** 返回 {accessToken, refreshToken, expiresIn(秒，7200), userInfo: UserMeVO}；**刷新** 返回 {accessToken, refreshToken, expiresIn}（refreshToken 轮换）。
- **ChatSessionVO**：id, goodsId, goodsTitle, goodsCover, peer{id, nickname, avatar}, lastContent, lastTime, unreadCount。POST /chat/sessions 返回 ChatSessionVO，主键字段为 `id`。
- **ChatMessageVO**：id, sessionId, fromUserId, toUserId, goodsId, content, type(1/2/3), readFlag(0/1), createTime。
- **改密** PUT /users/me/password {oldPassword, newPassword}。
- **价格建议** POST /price/suggest {categoryId, condition, originalPrice?, title?} → {suggestedPrice, minPrice, maxPrice, sampleCount, reason}（BigDecimal 两位小数）。需登录。样本取同分类已售（SOLD，价格取已完成订单 trade_order.price）及在售商品，样本不足时按原价×成色折旧系数估算；分类不存在/停用返回 20004，无样本且未填原价返回 80001「该分类暂无价格数据，请填写原价后再试」。配置项 campus.price.*、campus.recommend.* 见 /workspace/smart-module/README.md 第 4 节。
- **sort**：`latest`（默认，create_time 倒序）、`price_asc`、`price_desc`、`hot`（view_count 倒序）。
- **枚举**：商品状态 PENDING_AUDIT / ON_SHELF / RESERVED / OFF_SHELF / SOLD / REJECTED；成色 NEW / LIKE_NEW / GOOD / FAIR / POOR；交易方式 FACE / EXPRESS / EITHER；用户状态 NORMAL / BANNED；认证状态 NONE / PENDING / APPROVED / REJECTED；订单状态 PENDING / PAID / COMPLETED / CANCELLED；订单 action PAY / CANCEL / CONFIRM / REFUND；审核结果 APPROVE / REJECT；卖家 PATCH /goods/{id}/status 只允许 ON_SHELF ↔ OFF_SHELF。
- **订单流转（后端实现口径）**：PENDING -PAY(买家)→ PAID -CONFIRM(买家当面确认收货)→ COMPLETED；PENDING 或 PAID -CANCEL/REFUND(买卖双方)→ CANCELLED；无 DELIVER（总控定稿）。商品联动：下单时 ON_SHELF→RESERVED（UPDATE ... WHERE status='ON_SHELF'，影响行数 0 则 30003），取消/退款回 ON_SHELF，完成置 SOLD；列表只查 ON_SHELF。

## 12. 实现补充（后端 phase 1）
- 新增错误码：10005 手机号已注册；10006 验证码错误或已过期；10007 原密码错误；10008 已通过认证；10009 认证审核中；10010 学号已被认证；10011 用户不存在；20004 分类不存在或已停用；20005 商品当前状态不允许此操作（RESERVED/SOLD 不可编辑、删除、上下架）；70003 上传失败。
- `GET /users/{id}` 游客可访问。
- `POST /auth/logout` 需携带有效 accessToken，body 可省略。
- `pageSize` 超过 100 自动截断为 100。
- 详情：游客可看 ON_SHELF / RESERVED / SOLD；OFF_SHELF 返回 20002，PENDING_AUDIT / REJECTED 返回 20001；本人和管理员可看全部。
- 收藏：他人商品仅 ON_SHELF / RESERVED 可收藏；收藏/取消均幂等。
- **信誉分公式**：`credit_score = clamp(round(avg(收到的全部评分) × 20), 0, 100)`，每次新增评价后重算（详见第 13 节）。
- 文档：OpenAPI 中所有 `Long` 字段（主键/外键）标注为 `string`；`POST /auth/refresh` 返回 TokenVO `{accessToken, refreshToken, expiresIn}`（不含 userInfo）；`GET /goods/search` 的 keyword 必填（缺失返回 400）。

## 13. 实现补充（后端 phase 2）
- **新增错误码**：30004 订单不存在；30005 当前角色不能对该订单执行此操作（如卖家 PAY/CONFIRM）；40001 不能和自己聊天；40002 会话双方须包含该商品的卖家；40003 会话不存在；40004 消息内容无效；60001 商品不在待审核状态；60002 不能修改自己的账号状态；60003 不能封禁管理员；60004 认证申请已处理；60005 不能举报自己或自己的商品；60006 已举报，请等待处理（同一目标存在未处理举报）；60007 举报已处理；60008 公告不存在；60009 认证申请不存在；60010 举报不存在。非订单/会话参与方访问：HTTP 403 + code 403。
- **订单**：下单在同一事务内 `UPDATE goods SET status='RESERVED' WHERE id=? AND status='ON_SHELF'`（0 行 → 30003），写入 PENDING 订单（price 为下单时快照），提交后异步记录行为 4。商品非 ON_SHELF 时：RESERVED → 30003，OFF_SHELF/SOLD → 20002，其余 → 20001。状态变更全部为条件更新 `... WHERE id=? AND status IN (...)`，0 行 → 30001：PAY（买家，PENDING→PAID，写 pay_time）；CONFIRM（买家，PAID→COMPLETED，写 complete_time，商品 RESERVED→SOLD）；CANCEL / REFUND（买卖双方，PENDING 或 PAID→CANCELLED，写 cancel_reason，未填时默认「取消订单」/「退款」，商品 RESERVED→ON_SHELF）。无 DELIVER（传入返回 400）。
- **OrderVO**：id, goodsId, goodsTitle, goodsCover, buyer{id,nickname,avatar}, seller{id,nickname,avatar}, price, remark, status, cancelReason, payTime, completeTime, createTime, reviewed（当前用户是否已评价）。商品被删除后订单仍展示其标题/封面。
- **评价与信誉分**：仅 COMPLETED 订单（否则 50002），买卖双方各一次（否则 50001），被评价人为对方。每次新增评价后重算被评价人信誉分：`credit_score = clamp(round(avg(该用户收到的全部评分) × 20), 0, 100)`（四舍五入 HALF_UP；例：avg 4.5 → 90，avg 4.33 → 87）。ReviewVO：id, orderId, fromUser{id,nickname,avatar}, score, content, createTime。
- **聊天**：会话以 (goodsId, 双方用户) 唯一；双方之一必须是商品卖家（40002）。首次创建时若发起人不是卖家，记录行为 3。STOMP CONNECT 必须携带 `Authorization: Bearer <accessToken>`（有效、未退出、未封禁），否则返回 ERROR 帧并断开；只允许订阅 `/user/queue/**`。`/app/chat.send` 若会话不存在会自动创建；消息落库后推送 ChatMessageVO 给收发双方，会话 last_content（图片显示「[图片]」，商品卡片显示「[商品]」，文本截断 255 字）、last_time、接收方未读数同步更新。type=3 的 content 为前端序列化的 JSON 字符串 `{goodsId,title,coverUrl,price}`，后端原样存储，仅校验长度（≤2000）。STOMP 载荷与 HTTP 使用同一 JSON 规则（Long 为字符串、时间格式一致）。
- **封禁**：作废该用户全部 refreshToken，并写入 Redis 封禁标记（TTL 2h），其现有 accessToken（HTTP 与 STOMP CONNECT）立即失效；同时记录作废时间点 auth:revoked-before:{userId}（TTL 2h），签发早于该时间的 accessToken 即使解封后也无效；解封只移除封禁标记，用户必须重新登录（accessToken 带毫秒级 iatMs 声明用于比较）。STOMP 原生 /ws 与 SockJS 同一鉴权逻辑。管理员不能封禁自己（60002）或其他管理员（60003）。
- **审核**：商品与学生认证均只能审核 PENDING 状态（条件更新，否则 60001 / 60004），REJECT 时 reason 必填（400）；写 auditor_id / audit_time。学生认证 APPROVE 回写 sys_user.student_no / school 并置 APPROVED（学号被他人占用 → 10010）；REJECT 置 sys_user.student_auth_status = REJECTED，用户可重新提交。管理员上/下架仅 ON_SHELF ↔ OFF_SHELF，其他状态 → 20005。
- **举报**：处理结果只记录（APPROVE→APPROVED，REJECT→REJECTED），不自动下架或封禁，由管理员另行操作；ReportVO 附带 targetName（商品标题或用户昵称）。
- **公告**：PATCH 为 PUBLISHED 时写 publish_time（已发布再次发布不刷新）；PUT 只改标题与正文；DELETE 为物理删除。
- **游客可访问**（新增）：`GET /reviews`、`GET /announcements`、`GET /announcements/{id}`。
