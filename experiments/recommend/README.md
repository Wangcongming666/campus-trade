# 推荐算法离线实验（论文用，自包含可复现）

本目录是「基于 Spring Boot 的校园二手交易智能平台」智能推荐模块的论文实验。代码、脚本和结果都在这里，不依赖仓库其他目录。算法核心 `src/com/campus/trade/recommend/core/` 与后端 `backend/src/main/java/com/campus/trade/recommend/core/` 逐字节相同（从 `/workspace/smart-module/recommend-core` 复制）。

> **数据说明**：MovieLens-100K 是公开的**真实**评分数据；**Campus-Sim 是模拟数据**（由脚本生成，不是真实用户行为），其结果只用于算法对比，不能代表真实平台效果。下文所有校园数字和图标题都标注了"模拟数据"。

## 2. 复现

```bash
cd experiments/recommend
export JAVA_HOME=~/tools/jdk-17.0.21+9    # 任意 JDK 17；或保证 javac/java 在 PATH 中
bash run_all.sh                           # 默认划分种子 42,43,44,45,46
```

- 环境：JDK 17（不需要 Maven）；Python 3 + numpy、scipy、matplotlib。系统 Python 缺 scipy 时，脚本会自动建 `.venv` 并按 `requirements.txt` 安装（需联网）。中文图需要 Noto Sans CJK 等中文字体。
- 耗时（本机实测，2026-11-18）：全流程 **122 秒**。其中 Java 实验每个种子约 23 秒（MovieLens 约 8 s，MovieLens 冷启动协议约 7 s，Campus-Sim 约 8 s），汇总、检验和作图约 3 秒。
- 可复现性：划分、Random 方法和模拟数据都用固定种子。同一 seed 重复运行，`results/raw/run_metrics.csv` 逐字节一致。`dataset_stats.csv` 只有耗时列会变。
- 只跑部分种子：`bash run_all.sh 42,43`。

## 3. 数据集

### 3.1 MovieLens-100K（真实数据）

- 来源：GroupLens Research，<https://files.grouplens.org/datasets/movielens/ml-100k.zip>。943 名用户对 1682 部电影的 100,000 条评分，每人至少 20 条。
- 许可：只能用于研究；不得暗示明尼苏达大学或 GroupLens 背书；**不得再分发**（所以不入 git，由脚本下载）；未经许可不得商用；发表时须引用：
  > F. Maxwell Harper and Joseph A. Konstan. 2015. The MovieLens Datasets: History and Context. *ACM Transactions on Interactive Intelligent Systems (TiiS)* 5, 4, Article 19 (December 2015), 19 pages. DOI: 10.1145/2827872
- 处理：任何评分都视为一次隐式交互（二值）。MovieLens 只有"评过分"这一种行为，所以**行为加权不适用**，"CF 加权"在该数据集上就是 二值反馈 + IUF + 归一化。
- 兴趣通道怎么处理：MovieLens **没有注册兴趣**。物品分类取 `u.item` 里第一个为 1 的电影类型（19 类，只有 unknown 时归为 unknown）。冷启动兴趣通道只用"训练行为所在类型"推断兴趣（相当于线上"你常逛{分类}"的路径），注册兴趣一项为空。
- 冷启动：每个用户至少 20 条评分，8:2 划分后训练集至少 16 个物品，**没有自然冷启动用户**，所以全体用户上混合策略与 CF 加权完全相同（主表两行数字一致）。为了评估冷启动，另设 **"MovieLens 冷启动协议"**：在同一划分上，每个种子随机抽 20% 评估用户（均值 189 人），只保留每人 1~4 个（均匀随机）训练物品，测试集不变，所有模型在截断后的训练集上重新训练。这是人为构造的冷启动，不是真实新用户。

### 3.2 Campus-Sim（⚠️ 模拟数据）

`scripts/gen_campus_data.py` 生成，固定随机种子 `SEED=20261118`，输出 `data/campus/{users,goods,user_behavior,categories}.csv`，列名与后端 `user_behavior`、`goods` 表一致。运行 `python3 scripts/gen_campus_data.py data/campus` 会逐字节得到同样的文件。主要参数（脚本开头常量）：

| 参数 | 值 | 含义 |
|---|---|---|
| `N_USERS, N_GOODS, N_CATS, N_SUB` | 2000, 5000, 20, 5 | 用户、商品、分类、每分类子主题数 |
| 分类热度 | Zipf(0.8)，与均匀分布 7:3 混合 | 商品按分类热度分配 |
| 商品热度 | 对数正态 σ=1.3 | 长尾 |
| 注册兴趣 | 每人 1~3 个分类，各偏好 1 个子主题 | 冷启动兴趣通道的输入 |
| 活跃度 | 约 15% 新用户只有 1~4 次交互，其余对数正态 | 产生自然冷启动用户 |
| 交互落点 | 75% 落在兴趣分类内（其中 60% 在偏好子主题），否则按全局分类热度 | 决定兴趣通道的上限（见第 7 节） |
| 深度行为概率 `DEEP_P` | 随手浏览 (0.08,0.04,0.01)、兴趣分类 (0.18,0.10,0.04)、兴趣+子主题 (0.30,0.20,0.08) | 每次浏览后收藏/聊天/下单的概率，越匹配越高 |
| 时间范围 | 2026-11-01 之前 180 天 | 实验不做时间衰减 |

生成结果：59,005 条行为（浏览 43,014、收藏 9,013、聊天 5,687、下单 1,291），去重后 37,320 个用户-商品对，评估用户 1921 人，自然冷启动用户 369 人。价格字段（价格实验用）使用独立随机流，不影响行为数据。

## 4. 实验协议与方法

### 4.1 划分与冷启动定义

- 按用户 8:2 随机划分用户-物品对：交互 $n\ge2$ 个物品的用户，测试数为 $\max(1,\mathrm{round}(0.2n))$；只有 1 个物品的用户全部放进训练集（不参与评估）。划分种子 **42–46**，共 5 次，结果报告均值 ± 标准差（样本标准差，ddof=1）。
- 冷启动用户：训练集中交互物品数 $<\theta=5$（与线上 `cold-start-threshold` 一致）。Campus-Sim 的冷启动用户只取决于每人的交互数，5 个种子下都是 369 人。
- 邻居数 $K=40$（线上默认）。η 曾在 smart-module 中用 seed=7 选定，本目录只报告 42–46。

### 4.2 方法（用户点名的对比/消融组 + 参照）

| 代号 | 名称 | 兴趣表示 $r_{ui}$ | 相似度 |
|---|---|---|---|
| `popular` | **热度** | — | 按训练集行为加权计数排序（MovieLens 为评分次数），不衰减，过滤已交互 |
| `itemcf_pure` | **纯 CF** | 二值（不分行为类型） | 余弦，无 IUF，无归一化 |
| `cf_weighted` | **CF 加权** | 行为加权 1/3/4/5 + 封顶 10 + 对数压缩 $\ln(1+\cdot)$ | 余弦 + IUF + 行最大值归一化 |
| `hybrid_eta0.0` | **CF 加权 + 兴趣冷启动（η=0）** | 同上 | 冷启动用户只走兴趣分类 + 全局热度 |
| `hybrid_eta0.1` | **CF 加权 + 兴趣冷启动（η=0.1，线上取值）** | 同上 | 冷启动用户先放 $\lceil\eta N\rceil$ 个 CF 结果 |
| `usercf` | UserCF（参照） | 同 CF 加权 | 用户余弦，K=40 |
| `random` | Random（参照） | — | 均匀随机未交互物品 |

消融（只在 Campus-Sim 上有行为类型；MovieLens 跳过加权步骤）：纯 CF → +行为加权（对数压缩）→ +IUF → +归一化（= CF 加权）；另有"纯 CF + 只加归一化""线性加权（不做对数压缩）+ IUF + 归一化""混合 η=0.1 不用注册兴趣"。η 敏感性：η ∈ {0, 0.05, 0.1, 0.2, 0.3}。

### 4.3 公式

ItemCF（IUF 版）物品相似度与归一化、打分：

$$
w_{ij}=\frac{\sum_{u\in N(i)\cap N(j)} r_{ui}r_{uj}/\ln(1+|N(u)|)}{\sqrt{\sum_{u\in N(i)}r_{ui}^2}\sqrt{\sum_{u\in N(j)}r_{uj}^2}},\qquad
w'_{ij}=\frac{w_{ij}}{\max_k w_{ik}},\qquad
p_{uj}=\sum_{i\in N(u),\ j\in S(i,K)} w'_{ij}\,r_{ui}
$$

不带 IUF 时分子去掉 $\ln(1+|N(u)|)$；不归一化时直接用 $w_{ij}$。行为加权兴趣：$r_{ui}=\ln\bigl(1+\min(10,\sum_{b\in B(u,i)} w(\mathrm{type}_b))\bigr)$，权重为浏览 1、收藏 3、聊天 4、下单 5。

混合策略（`HybridRecommender`，与线上相同）：

```
if |N(u)| >= θ:  ItemCF(CF 加权) → 内容相似（离线不用）→ 全局热度补齐
else (冷启动):    [有种子商品] 先放 ⌈ηN⌉ 个 ItemCF 邻居（不足时内容相似；离线没有标题，不用）
                  其余：前 ⌈0.8·剩余⌉ 个在各兴趣分类（行为所在分类 ∪ 注册兴趣）的热度榜之间轮询，再用全局热度补齐
```

每个 N **单独调用一次推荐**，所以 CF 名额 $\lceil\eta N\rceil$ 按当前 N 计算，与线上按 `size` 计算一致。注意：N=10 时 η=0.05 和 η=0.1 的名额都是 1 个，两者结果相同。

### 4.4 指标

对评估用户集合 $U$，推荐列表 $R_N(u)$，测试物品 $T(u)$：

$$
\mathrm{P@}N=\frac{\sum_u |R_N(u)\cap T(u)|}{N|U|},\quad
\mathrm{R@}N=\frac{\sum_u |R_N(u)\cap T(u)|}{\sum_u|T(u)|},\quad
\mathrm{NDCG@}N=\frac1{|U|}\sum_u\frac{\sum_{p=1}^{N}\mathbb 1[R_N(u)_p\in T(u)]/\log_2(p+1)}{\sum_{p=1}^{\min(|T(u)|,N)}1/\log_2(p+1)}
$$

NDCG 采用二值相关、log2 折损，IDCG 按 $\min(|T(u)|,N)$ 个相关物品全部排在最前计算。覆盖率 $=|\bigcup_u R_N(u)|/|I_{train}|$；新颖度 = 推荐物品的平均 $\ln(1+\text{训练集流行度})$，**越小越新颖**。

### 4.5 显著性检验

按用户配对：每个用户一个观测，取其在 5 个种子中属于该子集的各次结果的平均（Campus 冷启动子集每个种子都是同样 369 人；MovieLens 冷启动协议每个种子抽到的用户不同，合并后 636 人）。主检验是双侧 Wilcoxon 符号秩检验（`scipy.stats.wilcoxon`，剔除零差值），同时给出配对 t 检验（`scipy.stats.ttest_rel`）。同一指标的 24 个对比一起做 Holm 校正。另外逐种子单独检验，统计"p<0.05 且方向一致"的种子数，用来看稳健性。指标为 NDCG@10 和 P@10（逐用户 hits/10）。

## 6. 结论（每条注明数据来源）

1. **CF 加权显著优于纯 CF 和热度**（来源：5.1、5.5；`significance.csv`）。在 MovieLens（真实）上，NDCG@10 从纯 CF 的 0.3499 升到 0.3772（+7.8%），P@10 从 0.2888 升到 0.3133；在 Campus-Sim（模拟）上 NDCG@10 从 0.0255 升到 0.0540。所有种子都显著，Holm 校正后 p<1e-10。
2. **各改进项的贡献**（来源：5.3 消融）。在 Campus-Sim（模拟）上，行为加权（对数压缩）贡献最大，NDCG@10 0.0255→0.0423；IUF 次之，→0.0507；归一化再到 0.0540，三步逐级都显著（Holm p<1e-10）。对数压缩必不可少：同样的权重线性叠加只有 0.0409，比对数压缩低 24%。MovieLens 没有多种行为，只能验证 IUF（+6.0%）和归一化（+1.7%），两项都显著。
3. **兴趣冷启动只在有"兴趣信号"的数据上有效**（来源：5.2、5.5）。
   - Campus-Sim（模拟）的冷启动用户上，混合 η=0.1 的 R@10 为 0.1165，是 CF 加权（0.0520）的 2.2 倍、热度（0.0428）的 2.7 倍；NDCG@10 为 0.0538，对比 CF 加权 0.0278。
   - 去掉注册兴趣后 R@10 降到 0.1035，NDCG@10 降到 0.0485，但校正后不显著（Holm p=0.058），只有 1/5 的种子显著。
   - 这一增益依赖生成器"75% 交互落在兴趣分类"的设定，属于模拟数据结论。
   - **不利结果**：在 MovieLens 冷启动协议（真实数据）上，按类型推断兴趣的混合策略**比直接用 CF 加权更差**（NDCG@10 0.1041 对 0.1311，Holm p=1.7e-04），也不如热度（P@10 0.0935 对 0.1031）。原因是电影类型很粗（Drama、Comedy 等覆盖面很大），而 1~4 部电影就足以让 ItemCF 找到相似电影。所以"交互数 < 5 就整体切换到冷启动"的规则在 MovieLens 上不合适；线上阈值应等真实数据积累后再校准。
4. **UserCF 在精度上更高**（不利结果；来源：5.1、5.5）。
   - 全体用户上，UserCF 在两个数据集都是 P/R/NDCG 最高：MovieLens NDCG@10 0.3890 对 CF 加权 0.3772（+3.1%，显著）；Campus-Sim 0.1015 对混合 0.0590（+72%）。
   - MovieLens 冷启动协议上，UserCF 也明显好于混合（0.1489 对 0.1136）。
   - Campus-Sim 冷启动子集上，UserCF 的 NDCG@10（0.0606）高于混合 η=0.1（0.0538），R@10（0.0992）低于混合（0.1165），两项差异都不显著（Wilcoxon p=0.588，t 检验 p=0.27）。
   - 代价是覆盖率和新颖度：Campus-Sim 上 UserCF 覆盖率 0.4013、新颖度 3.216，CF 加权为 0.8459、1.796。
   - 模拟数据是按"用户兴趣簇"生成的，天然有利于 UserCF。
   - 选择 ItemCF 作为线上主算法，是工程上的取舍：商品多于活跃用户、上新快；相似度可以离线缓存；能给出"因为你看过 X"的推荐理由；还能直接支撑"相似商品"接口。这不是因为 ItemCF 更准。
5. **η：覆盖率与召回率的权衡**（来源：5.4、`eta_sensitivity.csv`、fig4）。
   - 在 Campus-Sim（模拟）冷启动子集上，η 从 0 增到 0.3，覆盖率从 0.0385 单调升到 0.2271（5.9 倍）。
   - R@10 先略升后降：η=0.1 时 0.1165（N=10 时 1 个 CF 名额），η=0.3 时 0.1030。NDCG@10 单调下降，0.0569→0.0461，因为 CF 结果排在首位，挤掉了命中率更高的兴趣结果的位置。
   - η=0.1 对 η=0：R@10 +3.4%，不显著；NDCG@10 −5.4%，Wilcoxon 显著但 t 检验不显著（p=0.29），说明平均差很小、方向在不同用户间不一致；覆盖率从 0.0385 到 0.1096，约 2.8 倍。
   - 在 MovieLens 冷启动协议（真实）上，三项指标都随 η 增大而改善（NDCG@10 0.1041→0.1207，覆盖率 0.0678→0.1500），与上一条"ItemCF 对少量行为已有效"一致。
   - 结论：η=0.1 用很小的排序损失换来了约 3 倍的冷启动覆盖率，以及可解释的 CF 推荐，支持线上取 0.1。若更看重冷启动的首位准确率，η=0 的 NDCG 略好。
6. **热度推荐的马太效应**（来源：5.1）。热度的覆盖率极低（MovieLens 0.0298，Campus-Sim 模拟 0.0040），新颖度最差（5.866 / 4.573），只适合作为兜底。

## 7. 与 smart-module 旧结果的差异（如实说明）

- `smart-module/results`（单种子 42）里冷启动子集的混合策略 R@10 是 0.1220（η=0），本目录为 0.1127 ± 0.0156（η=0）。差异来自评估方式：旧实验对每个用户只调用一次 N=20 的推荐，再截取前 5/10。冷启动通道的兴趣名额是 $\lceil0.8\times20\rceil=16$，所以前 10 个全是兴趣结果。本目录对每个 N 单独调用，兴趣名额为 $\lceil0.8N\rceil$，CF 名额为 $\lceil\eta N\rceil$，与线上按 `size` 计算的行为一致。因此旧实验中"η=0.1 降低冷启动召回"的结论（当时名额按 N=20 算，是 2 个），在本协议下变为"R@10 基本持平、NDCG 小幅下降"。
- 用于全体用户的 CF 加权（smart-module 称 ItemCF-IUF）在 seed=42 上与旧结果一致（MovieLens P@10 0.3117，Campus 0.0296），说明划分与模型完全相同。
- 本目录新增了 NDCG、5 个种子、显著性检验、MovieLens 冷启动协议和逐级消融。"纯 CF"按用户要求定义为 二值 + 无 IUF + 无归一化；旧表中的"ItemCF"是 行为加权 + 归一化、无 IUF，两者不是同一个方法。

## 8. 局限

- Campus-Sim 是模拟数据，所有校园结论都要在上线后用真实埋点复测。MovieLens 是电影评分，与二手交易场景差异大。
- 离线实验没有商品标题，冷启动 CF 名额里的"内容相似"兜底没有参与评估；线上的"兴趣分类追加在售新商品""只浏览过仍在售的兜底层"也不在离线实验中（离线热度榜已覆盖全部训练物品）。
- 未调 K（固定 40）。K 敏感性见 smart-module 旧实验。
- 本实验没有改动算法核心，`src/.../recommend/core` 与后端一致。
